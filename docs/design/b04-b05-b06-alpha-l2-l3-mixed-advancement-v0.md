## Continuity and milestone trust boundaries

`scripts/b04_b05_b06_alpha_l2_l3_progression_v0.py` processes exactly **two authored candidate awards** at distinct source stages. A stage must have ended its full native Initiative round with four authentic G5 border exits and no pending attacks or reservations; all actors must be alive and mobile, and clocks must be in exploration. Advancement rejects active magical hosts, toxin/venom histories requiring new source authority, other pending clock milestones or borrowed source identities. The author candidate marker must follow a native scene terminal; it is **not** permission to award a level for a real table.

**G4.2 L1 initiative clock correction:** The original standalone L1 Alpha scene starts its first round internally. Both clean handoffs preserve the deadline and existing recovery event ID while adding the actual authored travel time (default 300 seconds per handoff). Older standalone #199/#200 L1 test scenes retain their original opt-out behavior; their evidence is not silently rewritten by this progression-specific correction.

L1→L2 and L2→L3 use the previous live G0 actor states as source, not new full-resource sheet defaults. Native existing G4.2 Recovery event IDs, original deadlines and current world seconds are carried into each clean separately instantiated source scene. Travel of **0–600 actual source seconds** per handoff is processed against the original G4.2 exploration clock (default 300); six-hour recovery or live cross-level toxin/effect rebinding is outside this bounded v0 and fails closed. The enemy in each new stage gets its own source-initialized resources; prior enemy HP/effects are **not** copied into a new species. Canonical source event SHA256, old/new party resource digest, GM candidate levels, each source actor path/digest, per-stage native ledger and final party state are retained.

The fixture stages each newly gained Max VP as Spent, preserving the old Available/Committed VP even when a new source profile increases the VP cap.
